## 現在地(2026-07-02)

v0.1 の技術検証はほぼ完了。パイプライン3部品(A: ポーズ抽出 / B: 認識モデル / C: LLM整形)が
一通り結線され、撮影→取り込み→エクスポート→辞書化→評価のループから手作業が消えた。
「仕組みを作る」フェーズから「**データを増やして精度を測る**」フェーズへ移行した。

```
手話動画

  → 部品C: LLM 整形(llm_shaping、①プロンプト試作済み)
  → 日本語
```

### 短期の最重要リスク

pipe-v2 基準(top-1 70% / top-5 90%)と実測(ミラー拡張あり top-1 27-29% / top-5 51-65%)の
ギャップが大きいことが確定した(2026-08-14)。ミラー拡張の効果自体は一貫している(なし:
top-1 8-10%・top-5 20-24% → あり: 27-29%・51-65%)が、それだけでは基準に届かない。
学習には無視できない実行間の揺れも残る(seed固定後も wgpu の非決定性で top-1 27-29% 程度は動く)。

**原因診断(2026-08-14、読み取り専用調査)**: モデルは約48-50万パラメータに対し、held-out学習に
使えるサンプルは51クラス×train=2件/ラベル(mirror拡張込みで4件)=204サンプル
(パラメータ数/サンプル数 ≈ 2,400倍)。300エポックでtrain lossが7.0→0.008まで低下しており、
汎化ではなく暗記が起きていると判断。誤りの大半は意味的に無関係な語への拡散(学習不足の兆候)だが、
数字語(ichi〜juu、51語中10語)同士の混同は一貫パターンがあり、ハンドシェイプの類似による
副次的な識別困難も重畳していると見られる。**テイク数3→5(train 2→4件、mirror込み4→8件)は
サンプル数を倍増させるが、この規模のモデル・クラス数に対しては依然として2〜3桁小さく、
単独でpipe-v2基準に届く可能性は低いと判定**(経験則ではこの規模なら1クラス数十〜数百件が目安)。

**2026-08-14 ユーザー決定**: 上記診断を踏まえた上で、pipe-v2基準を今は追わず
**「3テイクのまま単語数を増やす」ではなく「新規語から5テイクにしつつ単語数も増やす」**
方向で進める。v1.0 ロードマップの「広げた語彙から後で信頼語彙に絞り込む」設計思想と整合させ、
pipe-v2(リアルタイム化への移行基準)の達成は先送りにする。既存51語は3テイクのまま据え置き。
