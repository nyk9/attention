## 現在地(2026-07-02)

v0.1 の技術検証はほぼ完了。パイプライン3部品(A: ポーズ抽出 / B: 認識モデル / C: LLM整形)が
一通り結線され、撮影→取り込み→エクスポート→辞書化→評価のループから手作業が消えた。
「仕組みを作る」フェーズから「**データを増やして精度を測る**」フェーズへ移行した。

```
手話動画
  → 部品A: ポーズ抽出(pose_extractor、手ポーズ列 126次元)
  → 部品B: 認識モデル(transformer_burn、タグ + 確率の top-k)
  → 部品C: LLM 整形(llm_shaping、①プロンプト試作済み)
  → 日本語
```

### 短期の最重要リスク

**2026-08-22 更新**: pipe-v2 基準とのギャップは**大きく縮まった**。

```
2026-08-14: top-1 27-29% / top-5 51-65%
2026-08-22: top-1 68.8%  / top-5 88.4%   (目標 70% / 90%)
```

改善はすべて**追加撮影ゼロ**で得られた(手形記述子・z-score標準化・Palm検出ROIの中央正方クロップ)。

**これはロードマップ上の想定と食い違う。** 2026-08-16 に「次のレバーはテイク数 3→10(追加587テイク)」と
決定したが、**撮影を1本もせずに +40pt が出た**。587テイクは実績ペース(131本/日の日があった)なら
4〜5日の撮影に相当するが、それが今日1日の前処理改善を上回る保証はない。
**テイク数の決定は見直す価値がある(ユーザー判断待ち、まだ決めていない)。**

**残っている「撮影ゼロ」のレバーは S6(身体ランドマーク破綻)**。実験5で、人物 ROI を
フレーム外にはみ出したままクランプせずに BlazePose へ渡せば顔・肩が正しく取れることを目視確認した。
身体が取れれば「顔・肩を基準にした手の相対位置」が使え、実験3で効くと分かっている位置情報を強化できる。
実装・評価は未着手。

**注意すべき測定上の罠(今日新たに判明)**:

- `--seed` は学習結果を固定しない(同一シード反復で top-1 が sd 約1.5件ぶれる)。
  比較は**独立2標本検定 + 10 runs 以上 + レンジ併記**で行う
- **中間指標で判断しない**。手検出率で判断したために、実験4は有効な施策(CenterSquare)を一度捨てていた。
  判断は下流の認識精度で行う
