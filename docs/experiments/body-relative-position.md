# 実験7: 手首位置を肩中心・肩幅基準の相対座標にすれば精度が上がるか(S6 の実装と評価)

> **結論(先に)**: **身体ランドマークの取得は成功したが、手首位置を肩基準にしても認識精度は変わらなかった。**
> top-1 は 66.5% → 67.5%(差 +0.5 件、p=0.56)で差の証拠なし。top-5 は 88.8% → 87.2%(−0.85 件、p=0.06〜0.10)で
> 有意ではないがやや悪い側。**仮説(位置情報を身体基準にすれば効きが強まる)は支持されなかった。**

- **実施日**: 2026-10-12
- **ブランチ**: `feat/desktop-app` 上(未コミット)
- **前提**: [person-detection-roi.md](person-detection-roi.md) 第 6 節(S6 は人物 ROI をクランプせず BlazePose に渡せば直る見込み)/
  [handshape-tuning.md](handshape-tuning.md)(手首 xy を落とすと明確に悪化 = 位置情報が効く)
- **仮説**: 「手首の画像内座標は撮影日・立ち位置・カメラ距離の違いを含む。肩中心・肩幅で正規化すれば
  その分のノイズが消え、位置情報がより効く」

> **この文書の位置づけ**: 探索の結果報告であり、**決定事項ではない**。`CLAUDE.md` / `docs/development-plan.md` は書き換えていない。

## 0. 要約(確度つき)

1. **【実測・確度高】S6 の身体ランドマークは、人物 ROI を非クランプで渡せば取れる。** 全 153 テイク × 10 フレーム = 1530 フレームで
   人物検出・鼻・両肩の可視性条件を満たし(有効率 100.0%、有効フレームが 0 のテイクは 0/153)、目視でも顔の点が顔に、肩の点が肩に乗る(第 2 節)
2. **【実測・確度中〜高】手首を肩基準にしても top-1 は変わらない。** 各 20 run: base 33.9 件(66.5%、レンジ 29-38)/
   body-relative 34.4 件(67.5%、レンジ 31-39)。差 +0.5 件、Welch p=0.56、Mann-Whitney p=0.68
3. **【実測・確度中】top-5 は有意ではないがやや悪い側。** 45.3 → 44.5 件(−0.85 件、Welch p=0.058、M-W p=0.099)。
   「悪化した」とは言えず「改善はしなかった」が妥当
4. **【見立て・確度低】効かなかった理由の候補**(いずれも未検証、第 4 節)

## 1. 実装(既定の挙動は変えていない)

### 1.1 pose_extractor(`src/main.rs`)

- `add_body_anchors_to_dict`: **既存 dict に `body_sequence` を後付け**する。手特徴(`sequence`)には触れない
  (生成後に `pose_dict_full_center.json` と全テイクの `sequence` が完全一致することを確認済み)= 条件間で手特徴が同一の統制比較
- 選択フレームは build-dict の Uniform 選択と同じ `downsample_indices(nb_frames, 10)`(Uniform 以外の dict は拒否)
- 1 フレームの処理: 人物検出 → `person_region_square(FullBody, 1.25)` → **クランプせず**黒埋めで 256×256 → BlazePose
  → ランドマーク 0(鼻)・11・12(肩)を元座標へ戻す。可視性 `sigmoid(visibility) > 0.5` を 3 点とも満たすときだけ有効、それ以外は全ゼロ
- 8 次元/フレーム: `[鼻x, 鼻y, 左肩x, 左肩y, 右肩x, 右肩y, 有効, aspect(幅/高さ)]`(x/width、y/height 正規化)
- 駆動用 `#[ignore]` テスト `add_body_to_dict`(既存 dict 上書き禁止ガード付き)、目視用 `body_anchor_overlay`
- `build_dict_mode` / `live.rs` / 認識経路は変更なし

### 1.2 transformer_burn

- `handshape_features.rs`: `BodyAnchor`(テイク内**中央値**の肩中心・肩幅・aspect)、`take_body_anchor`、
  `wrist_relative_to_body`、`handshape_sequence_with_body`。**手首 xy 2 次元だけ**を
  `((wx - 肩中心x) / 肩幅, (wy - 肩中心y) * aspect / 肩幅)` に置換する(次元数 66・並びは不変)。
  左右反転して読むテイク(主たる手が左手枠)では肩中心 x も `1 - x` に反転
- `pose_data.rs`: `body_sequence`(任意)の読み込み、`PoseSample.body`、`to_input_features_with_body`
- `main.rs`: `--body-relative`(`--eval-holdout` 専用。`--save` / `--predict-pose` / `--drop-descriptor` と併用不可。
  前処理を保存済みモデルから復元できないため、`--drop-descriptor` と同じ流儀)
- アンカーが取れないテイクは従来の手首 xy にフォールバックし件数を表示する(今回は train 0/102、未見 0/51 件)
- ユニットテスト 3 件追加(中央値と無効除外、手計算オラクルとミラー時の x 符号、`anchor=None` の同一性と手首 xy 以外の不変)。
  既存テストは全通過(transformer_burn lib 56 / bin 58 / 他、pose_extractor 136+5)

## 2. 身体ランドマークの取得結果

| 項目 | 値 |
|---|---|
| 有効フレーム | 1530/1530(100.0%) |
| 有効フレーム 0 のテイク | 0/153 |
| テイク内の肩幅 平均のレンジ | 0.242 〜 0.350(x/width 正規化) |
| テイク内の肩幅の標準偏差の最大 | 0.042 |

**目視確認(`body_anchor_overlay`、arigatou-03 / iku-01 / anata-02 の各 3 フレームを生成し、うち 3 枚を確認)**:
顔の点(目・耳・口)は顔に、赤(鼻)は鼻の近くに、緑・青(両肩)は両肩の位置に乗っている。
現行の中央正方クロップで起きていた「39 点が顔と襟元に密集する」破綻は出ていない。
細部では、肩の点は肩の関節よりやや内側・上寄りで、iku-01 の鼻は実際の鼻から 15px 程度左にずれていた。
**S6 の診断(2 段パイプラインの前半が欠けていた)は実データで裏付けられた。**

注意: 腰から下は撮影画角に入っておらず評価していない。手のランドマークは従来どおり Hand 側。

## 3. 評価

条件は `handshape-tuning.md` の現在のベスト設定に揃えた: 手形記述子 + z-score 標準化、base、300 エポック、
`--eval-holdout` 既定分割(train 102 / 未見 51)。dict は CenterSquare(`pose_dict_full_center.json`)由来で、
**同一ファイル・同一 seed 列 1〜20**。差は `--body-relative` の有無だけ。

```bash
cd transformer_burn
./target/release/transformer_burn --eval-holdout data/pose_dict_full_center_body.json \
  --input-features handshape --model-size base --standardize [--body-relative] --seed <1..20>
```

| 条件 | top-1 平均 | top-1 レンジ | top-1 sd | top-5 平均 | top-5 レンジ | top-5 sd |
|---|---|---|---|---|---|---|
| base(手首は画像内座標) | 33.9 (66.5%) | 29-38 | 2.90 | 45.3 (88.8%) | 43-48 | 1.59 |
| **body-relative(肩基準)** | **34.4 (67.5%)** | 31-39 | 2.39 | 44.45 (87.2%) | 42-46 | 1.10 |

独立 2 標本として検定した(4.0 の方法論訂正どおり、`--seed` は結果を固定しないため):

| 指標 | 差(body − base) | Welch p | Mann-Whitney p |
|---|---|---|---|
| top-1 | +0.50 件 (+1.0pt) | 0.556 | 0.683 |
| top-5 | −0.85 件 (−1.7pt) | 0.058 | 0.099 |

読み取り:

- **top-1 は差の証拠なし。** 20 run のレンジが大きく重なる(29-38 と 31-39)。この標準偏差(約 2.5-2.9 件)では、
  20 run で検出できるのは 2 件(4pt)前後の差から
- **top-5 は p=0.06〜0.10 で、悪化とも同等とも言い切れない。** 悪化の傾きはあるが、検定上は有意ではない
- **ベースラインが実験5 の CenterSquare(68.8%、20 runs)より低い(66.5%)。** 同条件のはずだが
  `--seed` が結果を固定しないため、run 群ごとに平均が約 2pt 動く(実験5 のレンジ 61-76% の範囲内)。
  **条件間の比較は今回の同一 run 群内で行っており、その意味では妥当**だが、絶対値を実験5 と並べて読まないこと

## 4. なぜ効かなかったか(見立て。いずれも未検証)

1. **位置情報の効きがすでに頭打ち。** 実験3 で手首 xy を落とすと悪化することは分かっているが、
   「画像座標のままでも位置・動きの情報は十分に伝わっている」場合、基準を変えても増分は出ない。
   各撮影日の立ち位置・画角のずれが想定より小さい可能性がある(肩幅のテイク平均は 0.24〜0.35 と
   約 1.4 倍の幅はあるが、同一撮影日内ではほぼ一定のはず)
2. **誤分類の主因が位置ではない。** 実験3 の見立てでは高確信度の取り違えは「類似動作の語」や左右手ゆれ由来。
   位置の基準を変えても、これらは直らない
3. **肩ランドマークの精度。** 目視では肩の点が肩関節よりやや内側・上寄りで、フレーム間の揺れもある
   (テイク内の肩幅 sd 最大 0.042)。ここにテイク内中央値を使ったので揺れは抑えたが、
   肩幅という分母が不安定だと相対座標にノイズが乗る。手首 xy は 2 次元だけなので影響は限定的
4. **置換のみで追加はしていない。** 今回は「画像座標 → 肩基準」の置換で、顔・鼻基準の相対位置や
   肩・鼻の位置そのものを入力に足してはいない。顔の近く(額・口・胸など)で意味が変わる語の識別には、
   「手が顔のどこにあるか」という別の情報が要る可能性がある。これは**手首-鼻のオフセットを追加特徴にする**など別の設計で、本実験では未検証

## 5. 判定

### 「手首位置を肩基準にすると位置情報が強化され精度が上がる」: **支持されなかった**

- top-1 +0.5 件(p=0.56)で差なし、top-5 −0.85 件(p≈0.06〜0.10)でやや悪い側
- 少なくとも「置換」の形では、実装コスト(人物検出+BlazePose の追加推論、`body_sequence` の保持、推論経路の拡張)に見合う効果は観測されなかった

### 副次の「S6 の身体ランドマークが取れるか」: **取れる(確定的)**

- 有効率 100%(153 テイク全て)、目視で顔・肩が正しく乗る。S6 の破綻は人物 ROI の非クランプで解消する
- 他の用途(顔・体幹の位置を使う別の特徴、将来の Holistic 統合)の足場としては価値が残る

## 6. 制約と限界

- `--body-relative` は**評価専用**。保存済みモデルの `model_config.json` に前処理を記録できないため、`--save` / `--predict-pose` /
  動画→タグ直結パスでは使えない。採用するなら推論経路へのアンカー計算の組み込みが別途必要
- 評価分割は `--eval-holdout` 既定(テイク 3 を未見化)のまま。撮影癖と分割の噛み合わせ問題([[stage2-eval-holdout-pitfall]])は未解消
- 今回は CenterSquare dict のみ。full-frame / tiles3 では未実施
- 腰から下は評価不能(画角外)

---

## 7. 未確定のまま残る論点(いずれもユーザー判断)

- **`--body-relative` を残すか消すか。** 効果が出なかったため採用理由は弱いが、実装は小さく既定には影響しない
- **人物検出+BlazePose による身体アンカー生成(`add_body_anchors_to_dict`)を残すか。** 足場としては有用だが、現時点で消費する特徴は無い
- **別設計(手首-鼻オフセットの追加、肩・鼻位置そのものの入力化、フレーム単位のアンカー)を試すか。** 見立て 4 の検証になる
- **評価の検出力。** 20 run で見分けられるのは約 2 件(4pt)以上の差。小さな効果を測るなら run 数をさらに増やすか、
  評価分割のランダム化(未着手)と組み合わせる必要がある
- 実験5 から持ち越し: ROI 既定の変更、本番モデル `models/rec_full` の再学習、テイク数 3→10 の撮影方針の見直し
