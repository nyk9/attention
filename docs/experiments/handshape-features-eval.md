# 実験2: 手形記述子を認識モデルの入力特徴量にする

- **実施日**: 2026-08-21
- **ブランチ**: `explore/model-shrink-handshape`
- **目的**: 生の 126 次元ハンドランドマークの代わりに、幾何的な手形記述子を
  モデルの入力にしたら未見テイク精度は上がるか

## 動機

実験1([model-size-eval.md](model-size-eval.md))でモデル容量はボトルネックではないと分かった。
一方、先行調査で **学習を一切しない「手形記述子 + 最近傍探索」が top-1 約55-65%** を出しており、
同じ分割での学習済みモデル(top-1 27-29%)を大きく上回っていた。
つまり 126 次元の中に、モデルが取り出せていない情報が残っている。

生の 126 次元には学習に不都合な性質が2つある:

1. 左右の枠が撮影時の使用手で入れ替わる([[stage1-hand-switching-finding]])
2. 画像内の絶対位置・手の大きさ(カメラ距離)に依存する

手形記述子はどちらも構造的に解消する。

## 実装した記述子(1 フレーム 66 次元)

`transformer_burn/src/handshape_features.rs`。**1 手 33 次元 × 2 手 = 66 次元**。

| 範囲 | 内容 | 個数 |
|---|---|---|
| 0..15 | 各指の関節角(5 指 × 3 関節。[手首, MCP, PIP, DIP, TIP] の中間 3 点で測る) | 15 |
| 15..20 | 指先 - 手首の距離(スケールで割る) | 5 |
| 20..30 | 指先どうしの距離(スケールで割る) | 10 |
| 30..32 | 手首の画像内座標 xy | 2 |
| 32..33 | 検出フラグ | 1 |

- スケール = 手首 → 中指 MCP(landmark 9)の距離。手の大きさ・カメラ距離の代理
- 0..30 は**平行移動・スケール・左右反転のいずれにも不変**。位置と動きの情報は
  手首 xy(30..32)がフレームごとに持つ
- ブロックの順番は **主たる手 → 非主たる手**

### 主たる手の決め方

テイク単位(フレーム単位ではない)で、検出できたフレーム数が多い枠を主たる手にする
(同数なら右手枠)。主たる手が左手枠だったテイクは `pose_data::mirror_features` で
テイクごと左右反転し、常に「主たる手 = 右手枠」に揃える。

### モード

CLI `--input-features` の値。**既定は `raw` で、指定しなければ従来と同じ経路**。

- `handshape`: フレームごとに記述子を計算する(時間方向の情報が残る)。
  未検出フレームの当該手は、そのテイクで検出できたフレームの平均で埋め、検出フラグだけ 0 にする
  (ゼロ埋めは「全関節 0 ラジアン = 実在しない手形」を見せることになるため採らない)
- `handshape-mean`: テイク全体の平均記述子を全フレームに複製する。
  先行調査の最近傍探索と同じ内容(時間情報なし)。検出フラグにはカバレッジが入る

### 手が 1 フレームも検出されないテイク

全ゼロのベクトルを返す。学習から自動で間引くことはしない(取捨選択は `quality_flag` の役目で、
ここで暗黙に落とすと件数が合わなくなり原因追跡が難しくなるため)。

### ミラー拡張との組み合わせ(判断と理由)

**記述子を使うときはミラー拡張を適用しない。** 記述子の幾何部分(0..30)は左右反転に完全不変で、
かつ主たる手の正規化により反転しても同じ枠に入るため、`mirror_features` を通しても
**まったく同じベクトルの複製が増えるだけ**で拡張にならない(むしろ同一サンプルが 2 倍に
なることで実効的な学習率が変わる副作用だけが残る)。この不変性はユニットテスト
`handshape_features::tests::mirror_invariance` で担保している。

`--mirror-augment` と `--input-features handshape` を同時に指定した場合は、
黙って無視せず理由を表示して適用しない。

## 実装の検証(学習を介さない確認)

wgpu の非決定性で学習モデル側の数値はノイズが大きく、式や添字の書き間違いに気づけない。
そこで記述子そのものを最近傍探索で測る `#[ignore]` テストを置いた
(`tests/handshape_nn_test.rs`、`--eval-holdout` と同じ分割・train のみから z-score)。

```
手形記述子 + 最近傍(学習なし): gallery=102 probe=51
  top-1 31/51 (60.8%)   top-5 41/51 (80.4%)
```

先行調査の Python 実装(関節角 15 個のみ、top-1 54.9% / top-5 80.4%)と整合。
指先距離を足した分だけ top-1 が上振れしている。**書き起こしは正しい**と判断。

## 結論

**手形記述子は効いた。改善は大きく、一貫している。**

- base での比較で **top-1 が 16-33% → 47-55%**、**top-5 が 53-65% → 76-80%**。
  top-1・top-5 とも raw と handshape のレンジは重ならない。3 seed とも同一 seed 比較で
  handshape が上回っており、非決定性の揺れでは説明できない差
- 実験1で得た「raw ではモデル容量はボトルネックでない」という所見と合わせると、
  **ボトルネックは入力表現だった**と読める。同じデータ・同じモデル・同じ学習ループのまま、
  入力を作り直しただけで top-5 が 20 ポイント以上動いた
- `handshape`(フレームごと)と `handshape-mean`(テイク平均)は base ではほぼ同等で、
  top-5 は `handshape` がやや上(76-80% vs 71-76%)。**時間情報の寄与は小さい**。
  現在のデータが 10 フレーム/テイクと粗く、かつ 1 サイン = 1 語なので、
  動きより手形が支配的という先行調査の所見と整合する
- モデルサイズは記述子でも base が最良(top-1 47-55%)で、小さくすると下がる。
  raw のときと違い、**記述子では容量がある程度効いている**

### 期待に反した点(そのまま記す)

- **学習済みモデルは、学習なしの最近傍探索を top-1 で超えていない**
  (handshape base 47-55% vs 最近傍 60.8%)。top-5 では並んだ(76-80% vs 80.4%)。
  153 サンプルという規模では、Transformer を学習させるより記述子空間で直接引いた方が
  まだ強い。認識器の構成自体(最近傍 / プロトタイプ分類 など)を見直す余地がある
- **pipe-v2 基準(top-1 70% / top-5 90%)には依然届いていない**。
  top-5 は 90% までもう一息だが、top-1 は目標の 3 分の 2 程度

## 注意・限界

- 各条件 3 seed。レンジは真のばらつきの下限とみるべき
- 分割は `--eval-holdout` の既定のままで、撮影癖との噛み合わせという既知の問題
  [[stage2-eval-holdout-pitfall]] を引き継ぐ。ただし記述子は主たる手に正規化するので、
  この問題の主因(左右手ゆれ)には構造的に強いはず。改善幅の一部はここから来ている可能性がある
- 記述子の各次元は正規化していない(関節角 0..π、正規化距離 0..3、手首座標 0..1、
  フラグ 0/1 が同じベクトルに混在)。学習側で z-score 標準化を入れればさらに動く可能性があるが、
  今回は未検証
- 保存済みの実運用モデル(`models/rec_full`)は raw のまま。記述子版は保存していない
  (評価専用の使い捨て実行)

## 未確定のまま残る論点

- 記述子入力を本番モデルに採用するか(採用するなら `--input-features handshape` で再学習・保存)
- 入力の z-score 標準化を入れるか
- Transformer をやめて最近傍 / プロトタイプ分類にするか、あるいは併用するか
- `--eval-holdout` の分割ランダム化(実験1・2とも既定分割のまま)
