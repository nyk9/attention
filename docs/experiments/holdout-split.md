# 実験: `--eval-holdout` の分割方法(last / random / rotate)で評価は変わるか

> **結論(先に)**: 既知の落とし穴(撮影癖と分割の噛み合わせ)は**生の 126 次元では実在し、
> 現在の手形記述子では実質消えている**。`last`(従来の既定)が系統的に低いのは生特徴のときだけで、
> 手形記述子では `rotate` と同程度だった。ただし分割ごと(どのテイクを未見にするか)のブレは
> 手法間の差より大きい。

- **実施日**: 2026-10-12
- **ブランチ**: `feature/holdout-split`
- **dict**: `pose_dict_full_center.json`(CenterSquare、51 語 153 テイク)。ミラー拡張なし
- **前提**: [person-detection-roi.md](person-detection-roi.md)(評価の作法)/ メモリ `stage2-eval-holdout-pitfall`

> **この文書の位置づけ**: 測定結果の報告であり、**決定事項ではない**。`CLAUDE.md` は書き換えていない。
> 既定の分割方法は変更していない(`--holdout-split` 未指定 = 従来の `last` と完全に同一)。

---

## 0. 結論の要約

確度の高い順に:

1. **【実測・確度高】生の 126 次元では `last` が系統的に低い。** 学習=右手/未見=左手のズレで
   top-1 は `last` 10.1%、`rotate` で未見が「右手テイク」になる fold では 27.8〜29.4%
   (差 −9.0〜−9.8 件、Welch p<0.001、各 6 run)。過去の「stage 2 で top-1 5%」の説明と整合する
2. **【実測・確度高】手形記述子では `last` は系統的には低くない。** 手の不一致が 34/51 件ある
   `last` でも top-1 68.6%、不一致 5 件の fold 0 は 67.6% で差なし(p=0.62)。
   記述子が左右反転に不変なため、使用手のズレが精度に出なくなった(実験2 の設計意図どおり)
3. **【実測・確度中】どのテイクを未見にするかのブレが、手法間の差より大きい。**
   rotate の fold 別 top-1 は 67.6% / **79.4%** / 69.0%。fold 1(テイク2 を未見)だけ +5.5 件で、
   p<0.001。random は 1 run ごとに分割が変わり、レンジが 27〜42 件(sd 5.2)と最も不安定
4. **【実測・確度中】`rotate` 3 fold 平均が、最も情報量の多い推定。** 全テイクをちょうど 1 回未見にし、
   分割のブレを平均で消せる。手形記述子での値は top-1 **72.0%**(36.7/51)、top-5 **90.6%**(46.2/51)。
   `last` 単独(68.6% / 88.0%)より top-1 +1.7 件(Welch p=0.03、Mann-Whitney p=0.18 = 弱い証拠)
5. **【実測・確度低】手の不一致件数と精度の関係は、手形記述子では確認できない。**
   全 50 run をまとめた順位相関は −0.17(p=0.23)。random 内では −0.54(p=0.11、n=10)で、
   向きは予想どおりだが有意ではない

## 1. 実装

`transformer_burn`: `--holdout-split last|random|rotate`(既定 `last`)、`--holdout-fold k`(rotate 用)。

| 方法 | 未見テイクの選び方 |
|---|---|
| `last` | ラベルごとにテイク番号昇順の後ろ N 件(従来) |
| `random` | `--seed` とラベル名から決まる擬似乱数(自前 xorshift64*、依存追加なし)で N 件 |
| `rotate` | ラベルごとにテイク番号昇順の k 番目から連続 N 件(循環)。全 fold で各テイクがちょうど N 回未見になる |

分割後に「**手の不一致**」(未見テイクのうち、同ラベルの学習テイクに同じ使用手 L/R/LR が 1 つも無い件数)を
表示する。`rotate` の fold 2 は 3 テイクのラベルでは `last` と同じ分割になる。

- ユニットテスト 6 件を追加(`last` が従来と同一 / random の決定性・件数・重複なし / rotate の全 fold 網羅と
  循環 / 不一致件数の手計算オラクル / 引数解析)。既存テストは無変更で全通過(59 + 61)
- **整合性チェック**: `last` と `rotate fold=2` は同一分割。手形記述子で top-1 35.0 と 35.2(各 10 run)、
  生特徴で 5.2 と 4.5(各 6 run)と一致した

## 2. 測定

条件: 手形記述子 + z-score 標準化 + base(`--input-features handshape --model-size base --standardize`)、
300 エポック、ミラー拡張なし。生特徴は `--input-features` 未指定(標準化なし)。
各セルは 51 語中の件数。`--seed` は結果を固定しないので、独立 2 標本として扱った。

### 2.1 手形記述子(各 10 run)

| 分割 | top-1 平均 | top-1 レンジ | top-5 平均 | top-5 レンジ | 手の不一致 |
|---|---|---|---|---|---|
| last | 35.0 (68.6%) | 32-37 | 44.9 (88.0%) | 43-46 | 34 |
| random(分割も seed で変わる) | 35.9 (70.4%) | 27-42 | 46.8 (91.8%) | 45-50 | 10-21(平均 15.3) |
| rotate fold 0(テイク1 が未見) | 34.5 (67.6%) | 31-39 | 44.4 (87.1%) | 42-47 | 5 |
| rotate fold 1(テイク2 が未見) | **40.5 (79.4%)** | 38-44 | 48.8 (95.7%) | 48-50 | 7 |
| rotate fold 2(= last 相当) | 35.2 (69.0%) | 33-38 | 45.4 (89.0%) | 43-48 | 34 |
| **rotate 3 fold 平均** | **36.7 (72.0%)** | — | **46.2 (90.6%)** | — | — |

| 比較(top-1) | 差 | Welch p | M-W p |
|---|---|---|---|
| last − random | −0.9 件 | 0.61 | 0.91 |
| last − rotate 全 fold | −1.7 件 | 0.034 | 0.18 |
| last − rotate fold 0 | +0.5 件 | 0.62 | 0.51 |
| last − rotate fold 1 | **−5.5 件** | <0.001 | <0.001 |
| last − rotate fold 2 | −0.2 件 | 0.78 | 0.91 |

top-5 は last − random が −1.9 件(Welch p=0.016、M-W p=0.047)、last − rotate fold 1 が −3.9 件(p<0.001)。
それ以外は差の証拠なし。

### 2.2 生の 126 次元(各 6 run、手の不一致は上と同じ)

| 分割 | top-1 平均 | top-1 レンジ | top-5 平均 | top-5 レンジ |
|---|---|---|---|---|
| last | 5.2 (10.1%) | 2-9 | 14.0 (27.5%) | 12-17 |
| rotate fold 0 | 14.2 (27.8%) | 12-16 | 29.3 (57.5%) | 22-32 |
| rotate fold 1 | 15.0 (29.4%) | 12-18 | 27.7 (54.2%) | 26-29 |
| rotate fold 2(= last 相当) | 4.5 (8.8%) | 2-7 | 12.5 (24.5%) | 9-16 |

last − rotate fold 0: top-1 −9.0 件(p<0.001)、top-5 −15.3 件(p<0.001)。fold 1 でも同様。

## 3. 読み取り

- **(a) `last` は系統的に低いか**: 生特徴では**はい**(約 −9 件)。手形記述子では**いいえ**(±1 件以内)。
  fold 2 が `last` と同じ分割であり、生特徴で fold 2 だけ低いことが「テイク3 を未見にしたこと」が
  原因だと示している
- **(b) 不一致件数と精度**: 生特徴では不一致 34 件の 2 条件(last / fold 2)が 9〜10%、
  5〜7 件の 2 条件(fold 0 / fold 1)が 28〜29% と明確に分かれる。手形記述子では分かれない(上記 5.)
- **fold 1 が高い理由は不明**。テイク2 が学習側のテイク1・3 の「間」にあたり撮影条件が近い、
  などが見立てとして挙がるが、**検証していない**

## 4. 提案(既定は変更していない)

見立て(確度中):

- 日常の比較・施策の A/B には **`last` のままで足りる**(同じ分割どうしの比較なので歪みは相殺される)。
  ただし生の 126 次元や、使用手に敏感な新しい特徴を評価するときは `last` を使わない
- 「いまのモデルの汎化性能はどれくらいか」という**絶対値を報告する場面**では、`rotate` 全 fold の平均を使う。
  今回の手形記述子 + CenterSquare の値は top-1 72.0% / top-5 90.6%

## 5. 未確定のまま残る論点(ユーザー判断)

- **既定の分割を `last` から変えるか**。変えると過去の数値(全て `last`)と直接比較できなくなる
- **pipe-v2 基準(top-1 70% / top-5 90%)の判定にどの分割を使うか**。rotate 平均では 72.0% / 90.6% で
  基準付近に届くが、`last` では 68.6% / 88.0% で届かない。**基準のクリア判定そのものは決めていない**。
  なお全て同一人物・同一撮影環境のテイク間評価であり、別日・別人への汎化を測ってはいない
- rotate 平均の 1 回分は 3 fold × 学習 = 3 倍の計算コスト(現状 1 run あたり 1〜2 分)
- fold 1 の高さ(テイク2 が易しい)の原因調査をするか
- `rotate` は 3 テイクのラベルを前提に fold を回している。撮影が 10 テイクに増えたあとの fold 数
  (10 fold か、N 件ずつ k-fold か)の設計
- 生特徴の測定は 6 run のみ(手形記述子は 10 run)。結論の向きは明確だが、レンジの精度は低い

## 6. 再現手順

```bash
cd transformer_burn
C="--input-features handshape --model-size base --standardize"
D=data/pose_dict_full_center.json
# 従来(last)
cargo run --release -- --eval-holdout $D $C --seed 1
# ランダム分割(分割は --seed 由来)
cargo run --release -- --eval-holdout $D $C --holdout-split random --seed 1
# rotate(fold 0,1,2 をそれぞれ回して平均)
cargo run --release -- --eval-holdout $D $C --holdout-split rotate --holdout-fold 0 --seed 1
```

出力に `手の不一致: N/51 件` が出る。
