# ライブ経路の手検出の診断(live_diag)

日付: 2026-11-07 / ブランチ: `explore/live-hand-tracking`

## 目的

ライブ認識で手検出が途切れる・ずれる原因を切り分ける。`pose_extractor/src/live_diag.rs` の `#[ignore]` テスト2本で、
動画をカメラの代わりに、ライブと同じ Palm → Hand の経路で全フレーム流して分類した。

## 条件

- 対象: raw_jsl の ok テイク16本(ライブデモ L0 と同じ。1620×1080、30fps、計1670フレーム)。同一人物・同一環境
- ROI: full-frame(ライブの既定)と center-square
- 正解ラベルは無い。(b)(c) は教師なしの代理指標で、閾値はすべて仮置き
- 実行: `cargo test --release live_diag_report -- --ignored --nocapture`、`live_diag_timing`
- 同時にバグ修正: 出力ファイル名が `<rep>.mp4` の stem だけで、別の語の同番号テイクが上書きされていた。親ディレクトリ名を付けるようにした

## 結果

### 手検出(全体、stride=1)

| 項目 | full-frame | center-square |
|---|---|---|
| 手あり / 全フレーム | 666 / 1670 | 684 / 1670 |
| (a) 途切れ(手あり区間の途中、0.5秒以内) | 10区間 / 14フレーム | 8区間 / 9フレーム |
| (b) スパイク | 0.5% | 0.4% |
| (b) 手の大きさの急変 | 0.2% | 0.1% |
| (b) Palm枠と骨格の乖離 | 0.7% | **4.2%** |
| (b) 骨格がクロップ枠に接する | 5.6% | 4.6% |
| (c) 手1本で同じ手のスロットが変わった | 7.8%(36/460) | 4.9%(24/491) |
| (c) 2本が同じスロットを取り合った | 7.6%(13/171) | 7.4%(11/149) |

- 手なしフレームの大半(1004/1670)は、手を下げている区間(一人撮影の前後ラグ)。途切れは手あり区間に対して約2%
- 途切れの原因(full-frame、14フレーム): Palm がほぼ届いていたが閾値で落ちた5、**Palm は出たが Hand の presence < 0.5 で棄却9**。Palm が全く見えない途切れは0
- stride=2(約15fps 相当)では途切れが 4区間/5フレームに減る(間引くと粒度が粗くなるだけで、改善ではない)

### 目視(full-frame、フラグの多い3本の6枚から3枚を確認)

- `007_otsukaresama_05` f27(collide): 両手とも骨格は手に乗っている。ただし左手の骨格はやや不安定
- `017_wakaru_01` f14(swap): **骨格は手に正しく乗っている**。swap は「検出位置の誤り」ではなく handedness スロットの切り替わりだけ
- `020_ii_03` f26(drop_handrej): 人差し指を立てた手が写っているのに、Hand の presence < 0.5 で棄却されている(オーバーレイは薄い枠のみ)。**実際の取りこぼし**

### 時間(full-frame、中央値 ms)

| 段 | 前処理 | 推論 |
|---|---|---|
| Palm(毎フレーム) | **16.2** | 11.1 |
| Hand(手あり、1本あたり) | 1.0 | 6.7 |

Palm の前処理(クロップ+リサイズ+正規化)が Palm 推論より重い。追跡で Palm を省く場合も、前処理の高速化の方が効く可能性がある。

## 解釈と限界

- 検出の質は致命的ではない。途切れは少なく、骨格の大きなずれも1%未満。**ライブで精度が出ない主因が手検出の途切れだとは、この結果からは言えない**
- 気になるのはスロットの入れ替わり(約8%)。学習の特徴は左枠/右枠で構成されるため、ライブで同じ手が別の枠に入ると特徴が食い違う可能性がある。**精度への影響は未測定**
- center-square は途切れ・入れ替わりは少ないが、Palm枠と骨格の乖離が増える(0.7% → 4.2%)。差が実害かは未確認(既定は full-frame のまま)
- 16本・1人・1環境、各フレームは目視3枚のみ。閾値は仮置きで、他の人・環境・照明への一般化は未測定

## 未確定(判断待ち)

- Hand presence の閾値(0.5)を下げる、または直前フレームの結果で補う追跡を入れるか
- Palm 前処理の高速化に着手するか(撮影アプリが重い件 `todo-capture-performance` とも関連しうる)
