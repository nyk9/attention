# 実験1: 認識モデルの縮小と未見テイク精度の関係

- **実施日**: 2026-08-21
- **ブランチ**: `explore/model-shrink-handshape`
- **目的**: 51語×3テイク=153サンプルに対し、現行モデル(約48万パラメータ)は
  過大ではないかという仮説の検証。モデルを縮小したら未見テイク精度は上がるか

## 仮説

学習サンプル153件に対してパラメータ約48万は過剰で、モデルが訓練データを暗記して
汎化していない(`--train-pose` の in-sample が常に100%なのはその傍証)。
モデルを小さくすれば暗記の余地が減り、未見テイク精度が上がるかもしれない。

## 手順

```bash
cd transformer_burn
cargo run --release -- --eval-holdout data/pose_dict_full.json \
  --mirror-augment --seed <N> --model-size <P>
```

- データ: `data/pose_dict_full.json`(51語・153テイク、10フレーム×126次元)
- 分割: `--eval-holdout` 既定(各語のテイク番号の最後1件を未見)→ train 102 件 / 未見 51 件
- エポック: 既定300、学習率 0.0005、ミラー拡張あり(学習側のみ)
- プリセット P ∈ {base, small, tiny, micro} × シード N ∈ {1, 2, 3} = 12 回
- 参考としてミラー拡張なし(base)を seed 1, 2 で 2 回

**重要**: 学習は wgpu(GPU)バックエンドで浮動小数演算が非決定的なため、
`--seed` を固定しても実行ごとに結果が揺れる。以下は必ずレンジで読むこと。

## パラメータ数(実測)

`RecognitionModel::num_params()` を CLI が出力した値。51語(語彙 = タグ51 + SOS/EOS/PAD = 54)の場合。

| プリセット | d_model | heads | d_ff | layers | 実測パラメータ数 | config.rs のコメント |
|---|---|---|---|---|---|---|
| base  | 64 | 2 | 256 | 4 | **482,038** | 約483K(ほぼ一致) |
| small | 32 | 2 | 128 | 2 | **66,966**  | 約67K(一致) |
| tiny  | 16 | 2 | 64  | 2 | **19,174**  | 約19K(一致) |
| micro | 16 | 2 | 32  | 1 | **9,382**   | 約9K(一致) |

base だけコメントが 483K だが実測 482,038(482K)。誤差の範囲だが、正確には 482K。

## 結論

**縮小しても未見テイク精度は上がらなかった。仮説は支持されない。**

- top-1 のレンジは base(18-29%)が最も高く、small/tiny/micro のどれも base を上回らない
- top-5 も base(45-59%)と small(53-57%)・tiny(49-51%)がほぼ重なる程度で、
  縮小による改善は見られない
- micro(9K)だけは明確に悪化(top-5 22-35%)。ここは容量不足と読める
- ただし **tiny は base の 1/25 のパラメータ数で top-5 がほぼ同等**(49-51% vs 45-59%)。
  「48万パラメータが働いている」わけではなく、**モデル容量は今のボトルネックではない**
  ことを示している。縮小しても悪くならないが、良くもならない

つまり過学習を抑える方向(容量削減)では頭打ちであり、**ボトルネックはモデルサイズではなく
入力表現かデータ量の側にある**可能性が高い。これが実験2(手形記述子)の動機になる。

`--d-model` / `--num-layers` の個別指定によるさらに細かい探索は、
small/tiny が base を上回らなかった時点で打ち切った(探索する方向がない)。

## 注意

- 各条件 3 seed しか回していないため、レンジは真のばらつきの下限とみるべき
- 分割は `--eval-holdout` の既定(毎回テイク番号の最後を未見)のままなので、
  撮影癖(テイク3が左手になりやすい)と噛み合う既知の問題
  [[stage2-eval-holdout-pitfall]] を引き継いでいる。プリセット間の**比較**には
  同じ分割を使っているので有効だが、**絶対値**は実運用精度の推定として楽観視できない
