# サブワード分解(サブラベル化)の実現可能性調査 — Phase 1 報告

作成日: 2026-08-21 / ブランチ: `explore/subword-decomposition`

> **この文書の位置づけ**: 探索(スパイク)の結果報告であり、**決定事項ではない**。
> CLAUDE.md / `docs/development-plan.md` の方針欄はこの文書の内容では書き換えていない。
> 「確度」と「根拠」を分けて書く。数値はすべて出典(実測スクリプト or 論文)を持つ。

## 0. 調べたこと

仮説: **手話の1単語を「手形/動き/位置/向き」のサブラベルに分解してモデルの出力にすれば、
新語を少ないデータで学習できるのではないか。**

Phase 1 として以下を並列に調査した。

| # | 観点 | 方法 |
|---|---|---|
| a | 既存データからサブラベルを機械的に導出できるか | `pose_dict_full.json`(51語×3テイク)を実際に分析。標準ライブラリのみで記述子・k-means・1NN を自前実装 |
| b | 手話言語学と先行研究は仮説を支持するか | 論文調査(Cooper 2012 / Kezar 2023,2025 / Bilge 2022 ほか)+ JSL 資源の有無 |
| c | 機械導出が無理な場合、人手アノテーションの工数は | `words.tsv`・`index.tsv` の実体と既存ツール資産から試算 |
| d | モデル側の変更案・検証計画 | working tree の `recognition.rs` / `config.rs` を読んで設計 |

a の中心的な数値は、別実装で独立に再現できるか確認した(下記 3.4)。

## 1. 結論の要約

**確度の高い順に:**

1. **【実測】手形は、既存データから機械的に導出できる見込みが高い。** 手首原点・スケール正規化
   した手形記述子は、同一単語の別テイクどうしが十分に近い。動き・位置は現データでは困難。
2. **【実測・想定外】この調査の副産物として、学習を一切しない手形記述子 + 最近傍検索が、
   学習済み認識モデルを同じ分割で大きく上回った**(top-1 55-65% vs 27-29%、top-5 80-89% vs 51-65%)。
   これは**サブラベル化の話とは独立に、現在のボトルネックが特徴量ではなくモデル/学習側にある
   ことを示唆する**。本 Phase 1 で最も実務価値が高い発見はここだと考える。
3. **【文献】仮説そのものは先行研究で実測されているが、その効果は「大語彙・多データの中の
   少数例クラス」で確認されたもので、70語規模の本プロジェクトには当てはまらない公算が大きい。**
4. **【文献】位置パラメータは身体基準でしか定義できず、手のみ126次元では原理的に取れない。**
   先行研究では位置が最も情報量の大きいパラメータだった。S6 の身体ランドマーク問題を先に解く
   必要があり、**順序が逆**になる。
5. **【調査】JSL には ASL-LEX に相当する音韻パラメータ付きデータベースが存在せず、
   JSL の音韻目録自体に定説がない**(手型21種 vs 基本手型3〜4種と、文献間で一桁違う)。
   サブラベルの正解は自前で作るしかない。
6. **【試算】人手アノテーションは 74語時点で 13〜38時間**(混合案)。ただし最大のリスクは工数
   ではなく**循環性**(撮影者=アノテーターのため、ラベルが「実際に産出された形」ではなく
   「本人が意図した形」になり、系統誤差が in-sample 指標では検出できない)。

**総合すると、現時点でサブワード分解に本格投資することは勧めにくい。** ただし、これは
「仮説が間違い」という意味ではなく「**適用する時期が来ていない**」という判断材料である。

## 2. (a) データからの機械的導出 — 実測結果

分析スクリプトと生出力はスクラッチパッド(`subword-analysis-report.md` ほか)に保存。
リポジトリのデータは読み取りのみで変更していない。

### 2.1 まずデータ品質(想定より悪い)

| 指標 | 実測 |
|---|---|
| 全1530フレーム中、両手とも未検出 | **964(63%)** |
| 主たる手が検出できたフレーム数 | テイク平均 **3.57 / 10** |
| max カバレッジ 0.5 未満のテイク | 136 / 153 |
| 同一フレーム内で両手が同時に取れたテイク | 37 / 153 |
| 主たる手がテイク間で食い違う語 | **51語中46語**(既知記述の「41語中34語」より広い) |

10フレームのうち平均3.6フレームしか手が写っていない。**動き記述子が壊れる直接の原因**であり、
サブラベル以前のデータ品質の問題として独立に重要。

### 2.2 記述子ごとの判定

`--eval-holdout` と同じ分割(gallery = テイク01/02、probe = テイク03)での最近傍単語検索。
51語からの検索なので偶然は top-1 約2.0% / top-5 約9.8%。

| サブラベル | 判定 | top-1 | top-5 | 備考 |
|---|---|---|---|---|
| **手形**(関節角+指先間距離) | **有望** | **65.2%** | **89.1%** | 主たる手の正規化なしでも同値(記述子が鏡映不変) |
| 向き(手のひら法線) | 条件付き | 26.1% | 60.9% | 正規化なしだと 6.5% に崩壊 |
| 位置(画像内座標) | 条件付き | 13.0% | 43.5% | 3x3ゾーンは実質4ゾーンしか使われず、88%が2ゾーンに集中 |
| 動き(手首軌跡) | **困難** | 17.4% | 28.3% | 1フレーム除去で記述子が平均27.3%変動(手形は5-7%) |
| 生の126次元(参考) | — | 4.3% | 13.0% | 現行モデルの入力そのもの |

### 2.3 sanity check は期待どおりの構造を示した

- **数詞10語**(手形が体系的に違い、動き・位置はほぼ共通)→ 手形 1NN **96.7%**、動き 26.7%、位置 10.0%
- **挨拶語**(動き主体)→ 手形は 41.7-50.0% に落ち、位置 45.8% が相対的に効く
- クラスタの中身も言語的に整合(roku/nana/hachi = 親指系、ichi/juu/kuru = 人差し指系)
- 手形が混同する対(konnichiwa↔konbanwa、ookii↔chiisai、suki↔kirai など)のうち4対は
  動きか向きが実際に補った。ただし各対 n=6 で、統計的な主張はできない

### 2.4 ただし「離散カテゴリの自動付与」はまだ無理

- 連続記述子は安定しているが、**離散化すると崩れる**。5ビットの伸展指コードはテイク間一致 61%、
  3テイク完全一致した語は 43% にとどまる
- k=17 の k-means で単語内テイクが同一クラスタに入る率 0.641-0.650(チャンス比 7.6-8.4倍)、
  3テイク完全一致 49-52%
- つまり「**手形を連続ベクトルとして扱うなら十分安定、離散な手形IDを自動で振るのはまだ不可**」

## 3. 副次発見: 学習なしの最近傍が学習済みモデルを上回る

**これは当初の調査目的の外側で出た結果だが、最も実務的な含意を持つ。**

| 手法 | 分割 | top-1 | top-5 |
|---|---|---|---|
| 学習済み認識モデル(ミラー拡張あり、seed 1-3) | `--eval-holdout` | 27-29% | 51-65% |
| 生126次元の最近傍(学習なし) | 同左相当 | 4.3% | 13.0% |
| **手形記述子の最近傍(学習なし)** | 同左相当 | **65.2%** | **89.1%** |

### 3.1 独立実装での再現(私自身が別に書いて確認)

サブエージェントの実装を使わず、関節角15個の平均のみ・距離特徴なし・z-score は gallery
だけから算出(probe を見ない)という、より単純で保守的な実装で再検証した:

- probe = テイク03(46語分): **top-1 56.5% / top-5 82.6%**
- probe = 各語の最終テイク(= `--eval-holdout` と完全に同じ分割、全51語):
  **top-1 54.9%(28/51) / top-5 80.4%(41/51)**

数値はサブエージェント版より低いが、**桁は一致し、学習済みモデル(27-29% / 51-65%)を
明確に上回る**。pipe-v2 基準(top-1 70% / top-5 90%)に対しても、top-5 は届きうる水準にある。

### 3.2 解釈(確度: 中)

- **言えること**: 現在の126次元特徴量には、学習済みモデルが取り出せていない単語識別情報が
  かなり残っている。ボトルネックは「特徴量に情報が無い」ことではなく、
  **153サンプルに対して482Kパラメータのモデルを学習させている構成そのもの**の可能性が高い
- **言えないこと**: 「最近傍のほうが良いモデルだ」とは言えない。最近傍はノンパラメトリックで
  学習データを推論時に全部使う別種の手法であり、語彙が増えると計算量が線形に増える
- **除外できない交絡**: 同一単語の3テイクは連続撮影のため、照明・服装・立ち位置などの
  セッション相関で最近傍が有利になっている可能性を、現データからは排除できない
  (別日に撮り直したテイクで検証する必要がある)

## 4. (b) 文献の裏取り

### 4.1 仮説を支持する証拠(いずれも実測値がある)

| 研究 | 内容 | 効果 |
|---|---|---|
| Kezar et al., Sem-Lex Benchmark (ASSETS 2023, arXiv:2310.00196) | ASL-LEX 2.0 の16音韻素性を補助タスク化 | ISR top-1 67.7%→71.3%。**学習4例のクラスで 62.2%→68.2%(+6pt)** |
| Kezar, Sehyr, Thomason (2025, arXiv:2509.04745) | train/test の語彙が互いに素な split | 未知語 ISR の MRR 0.381→0.452 |
| Bilge et al. (TPAMI 2022, arXiv:2201.05914) | 手形/向き/位置/動き等の53次元バイナリ属性でゼロショット | 未知50語 top-1 31.3% / top-5 66.0%(偶然 2.0% / 10.0%) |

「少データで効く」「未知語に汎化する」は、**実際に測られている**。

### 4.2 本プロジェクトに当てはまらない理由(こちらのほうが重い)

1. **「少データ」の意味が違う。** 上記はすべて「3,149語・84,568本」規模の中の少数例クラスの話。
   音韻ヘッドは他の数千語から表現を学べる。**語彙70語の環境には転移元が存在しない**
2. **10テイクでは効果がほぼ消える。** Sem-Lex では学習10例のクラスで +0.7pt(72.3→73.0%)。
   本プロジェクトが次の撮影ラウンドで到達する水準(全語10テイク)は、
   文献上まさに**恩恵が最小の領域**
3. **位置が原理的に取れない。** ASL-LEX も Bilge の属性も、位置は chest / forehead / ear など
   **身体基準**。Cooper et al. (JMLR 2012) の2D実験では **Location 単独 60.5%(最強)に対し
   HandShape 単独 3.4%**。手のみ126次元では、最も情報量の大きいパラメータだけが表現できない
4. **JSL に流用できる資源がゼロ。** ASL-LEX(2,723語、CC BY-NC 4.0)に相当する JSL DB は
   見つからず、JSL 音韻目録に定説もない(米川1984: 手型21 / 市田2005b: 基本手型3〜4)。
   JSL Colloquial Corpus(Bono et al., LREC 2014、40時間・27,371トークン)は存在するが、
   **音韻/手形の層があるという記述は見つからなかった**。ASL-LEX は「記述スキーマの借用元」には
   なるが「JSL のラベルを得るデータ源」にはならない

### 4.3 負の証拠

- Kezar 2025 で**パラメータ分解を単独適用すると認識は 0.381→0.372 に悪化**した
  (効いたのは分解ではなく音韻ラベルという教師信号)
- Kezar (arXiv:2310.00195) では素朴なマルチタスクがカリキュラム学習に負けた
- Cooper et al. (2012) の「データが少なくて済む」は rationale として書かれただけで、
  **アブレーション実験は存在せず**、未知語実験もない(そこでの unseen は同一語彙の held-out テイク)

## 5. (c) 人手アノテーションの工数試算

前提を置いた試算であり、確定値ではない。

| 案 | 単位 | 74語時点 | 400語時点(累計) |
|---|---|---|---|
| A: 語単位のみ | 74項目 | 10〜30h | 24〜66h |
| B: テイク単位フル | 740項目 | 25〜60h | 90〜170h(単独では非現実的) |
| **C: 混合(語単位で基本形 + テイク単位で軽量差分)** | — | **13〜38h** | 40〜110h |

- 選択式UI・1語あたり初回2.5〜7.4分/習熟後1.3〜2.6分を仮定
- ツール: ELAN + `elan_parser` 拡張が +8〜22h(v1 は単一tier・ALIGNABLE のみなので多tier対応が必要)、
  自作CLIが +8〜20h。**ELAN 経路は協力者レビューの受け入れ基盤と重なるため、仮説が不発でも資産が残る**
- `pose-extract` のオーバーレイ動画の一括生成は **TTY必須CLIのためバッチ経路が無く**、
  非対話パスの追加に 2〜6h + 無人実行 6〜12h

### 5.1 最大のリスクは工数ではなく循環性

撮影者=アノテーター(ろう者でも手話音韻の専門家でもない)なので、ラベルは
「実際に産出された形」ではなく「**本人が意図した形**」になる。誤った産出に誤ったラベルが
整合的に付くため、**系統誤差として学習され、in-sample 指標はむしろ良く見え、内部検証では
検出できない**。1名体制では inter-annotator agreement を原理的に測れない。
危険度は 手形 > 向き >> 動き > 位置 > 両手性。

### 5.2 タイミングの論点

74語・手形目録40〜60種では、**1手形あたり平均1.2〜1.9語**しかない。
サブラベル化の主な利得である**パラメータ共有がほとんど発生しない**規模である。
理屈上の投資タイミングは 200〜400語規模(v0.3〜v0.5)。

なお、テイク間変動の主因である「利き手の持ち替え」は `--inspect-dict` の `used_hands` で
**すでに機械取得できている**。テイク単位フルラベリングの価値の大部分は人手なしで入手済み。

## 6. (d) モデル側の変更案(設計のみ、実装はしない)

### 6.1 現行構造の実測

- 既定寸法(`config.rs`): d_model=**64**、num_heads=2、d_head=32、d_ff=256、num_layers=4
  - **CLAUDE.md の「d_model=16、d_ff=64」は現行コードと一致しない**(下記 8 参照)
- パラメータ数の内訳(概算)

| 部位 | 概算 |
|---|---|
| Encoder input_projection (126→64) | 8.1K |
| Encoder TransformerBlock ×4 | 200K |
| Decoder embedding + layer×4 + output_projection | 274K |
| **合計** | **約 482K** |

学習サンプルは153件。**パラメータ数はサンプル数の約3000倍**。
サブラベル化は出力表現の変更であって、この比を改善するものではない。

また `predict_topk` は SOS 1トークンだけ入れて最初の位置の分布を見ており、
**実質51クラス分類器を Seq2Seq の器で回している**。単語認識にはこの器は過剰である。

### 6.2 案1: マルチヘッド分類(推奨・最小)

Decoder(274K)を使わず、Encoder 出力をプールしてパラメータごとの小さな線形ヘッドを並べる。

```
pose [B, T, 126] → PoseEncoder → h [B, T, d_model]
  → pool(mean、または学習可能な1クエリの attention pooling) → z [B, d_model]
  → head_handshape_dom    : Linear(d_model, |HS|)
  → head_handshape_nondom : Linear(d_model, |HS|+1)   # +1 = 片手サイン
  → head_movement / head_location / head_orientation
loss = Σ_p w_p * CrossEntropy(head_p, target_p)
```

単語の予測は**合成スコア** `score(word) = Σ_p log softmax(head_p)[param_p(word)]`。
語彙表(word → パラメータ組)さえあれば、**学習に一度も出てこない単語も候補に入る**
(仮説の核心)。パラメータ増は約8K で、Decoder を落とせば **482K → 約215K と むしろ減る**。
「モデルスケールアップは保留」方針と矛盾しない。

### 6.3 案2: マルチタスク(既存 flat head を残す)

案1のヘッド群を既存 Decoder と並列に足す(`loss = L_flat + λ Σ L_p`)。
サブラベル教師がノイジーでも flat 経路が壊れない利点があるが、パラメータは増える。

### 6.4 案3: ターゲット列だけ差し替える(最安のプロトタイプ)

`pose_data.rs::batches` が作る `[SOS, タグID, EOS]` を `[SOS, HS, MOV, LOC, EOS]` に変え、
`TagVocabulary` をサブラベル値の和集合にすれば、**モデルのコードを変えずに**
サブラベル列の自己回帰生成になる。ただし `predict_topk` が位置0しか見ていないため、
位置別マスク付きのスコアリングを書き足す必要がある。

**いずれの案でも、`recognition.rs` / `recognition_training.rs` は触らず別モジュール
(例: `subword_recognition.rs`)として足すこと。** 保存済みモデルと `model_config.json` の
後方互換を壊さない。working tree に `--model-size` の未コミット作業があるため `config.rs` は要注意。

## 7. 仮説の検証計画

### プロトコル A: leave-N-words-out(未知語ゼロショット)

51語のうち W 語を**全テイクごと**学習から外し、残りで学習。未知語のパラメータ組を語彙表に
足しただけの状態で合成スコアリングする。
比較対象は **flat モデルではなく偶然**(flat は未知語を構造上 0% でしか当てられない)。

### プロトコル B: データ効率曲線

未知語の学習テイク数 k = 0,1,2,3 で flat と subword を比較。仮説が正しければ
**k が小さいほど subword 有利、k が大きいと差が消える**という曲線になるはず。
この形が出るかどうかが最もはっきりした検証になる。

### プロトコル C: アノテーション不要の事前ゲート(最も安い)

サブラベル教師を1つも作らずにできる予備調査。**本 Phase 1 で実質的に一部を実施済み**
(3章の最近傍検索がこれに当たる)。残りは:
- 少数の語だけ手でパラメータを付け、既存の誤り(sumimasen→onegaishimasu 等)が
  「パラメータの近さ」で説明できるかを確認する(数十分)
- **文献側からの提案**: 70語に手形・動き・両手性を粗く付け、
  **サブラベルの組が語を一意に決められるか**を確認する。多数が同じ組に落ちるなら
  この語彙規模で仮説は成立しない。撮影もコードも不要

### 測定上の落とし穴(既知)

| 落とし穴 | 対策 |
|---|---|
| wgpu の非決定性で top-1 が 27-29% 程度ブレる(seed固定後も) | 全条件 3 seed 以上、**レンジで報告**。単発比較は禁止 |
| 撮影癖(テイク3=左手)と holdout 分割の噛み合わせ | 語を丸ごと外すプロトコルAでは形が変わる。`--inspect-dict` の使用手分布を必ず添える |
| n=51語では数語の差が誤差 | 語ごとの正誤を全部出す。集計値だけで判断しない |
