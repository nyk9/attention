# llm_shaping - タグ列 → 自然な日本語(部品C)

手話認識パイプラインの最終段。認識モデルが出したタグ(+確率)を、
自然な日本語文に整形する。

```
手話動画
  → 部品A: ポーズ抽出(pose_extractor、手ポーズ列 126次元)
  → 部品B: 認識モデル(transformer_burn、タグ + 確率の top-k)
  → 部品C: LLM 整形(このディレクトリ)← いまここの ① 試作
  → 日本語
```

## 方針

CLAUDE.md のロードマップどおり **①プロンプト → ②LoRA → ③自作** の順で安く試す。
このディレクトリは①の成果物。コードはまだ無く、プロンプトと検証記録のみ。

## ファイル

- `prompt_v1.md` — プロンプト本文(語彙表・整形ルール・入出力形式)と使い方
- `eval_v1.md` — v1 の検証記録(テストケース8件と所見、v2 候補)

## 使い方(現状は手動)

1. `prompt_v1.md` のプロンプト本文を Claude(claude.ai / API)のシステムプロンプトに置く
2. 認識モデルの top-k 出力(`transformer_burn --predict-pose` または pose-extract の
   「動画からタグを認識」)を入力形式に写して渡す
3. 「整形結果」と「採用タグ」(? = 低確信)を受け取る

## 検証の要点(詳細は eval_v1.md)

- 1語素通し・過剰生成の抑止・不確実性の明示(?)は v1 で動く
- 文脈による top-k 挽回は「top-1 の組が意味的に破綻」しているときのみ発動。
  現語彙50語では発動機会が少なく、**②(LoRA)への投資判断は文(複数サイン)認識が
  動き出してからで十分**とみている
- 高確信度の単発誤り(stage 1 の左右手ゆれ由来)は部品Cでは救えない(認識側の課題)
- 検証はセッション内スモークのみ。**API 経由の独立実行での再検証が未実施**である点に注意

## 語彙表の同期ルール

プロンプト内の語彙表は `transformer_burn/data/raw_jsl/words.tsv` から生成している。
words.tsv や認識モデルのタグ語彙(tag_vocab.json)を変えたら語彙表も更新すること。
word_id 022 は words.tsv 上で未決定(`???`)のため含めていない。
